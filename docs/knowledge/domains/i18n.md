# i18n(中英双语 + LLM 输出语言切换)

全应用文案 + 字段词典 + LLM 起草输出 都按用户选定语言切换。无外部 i18n 库,手撸轻量 Context + 类型化字典。

## 架构

```
LanguageProvider (main.tsx 包 App)
  ├── detectInitialLang(): localStorage > navigator.language(zh-* → zh,其他 → en) > 默认 zh
  ├── state: lang
  └── value: { lang, setLang, t: DICTS[lang] }
       │
       ▼ useLanguage() 散布全应用
         ├── Header 右上语言切换按钮(Languages 图标 + 切换)
         ├── 所有 UI 文案:t.app / t.header / t.banner / t.composer / t.editor / 
         │                t.palette / t.textElems / t.gallery / t.detail / t.config / 
         │                t.picker / t.flash / t.jobs
         ├── 字段词典:lang 决定显示 opt.zh 或 opt.en
         └── API 调用:draftPrompt({input, lang}) → 后端 prompt-engine 用 lang
                                                  注入"输出语言"系统指令(zh/en)

后端:packages/shared/src/api.ts
  OutputLang = "zh" | "en"
  DraftPromptRequest.lang?: OutputLang

apps/api/src/domain/prompt-engine/system-prompt.ts
  getPromptEngineSystemPrompt(lang) =
    BASE_SYSTEM_PROMPT + "\n\n" + LANG_INSTRUCTION[lang]
  LANG_INSTRUCTION.zh: "所有字符串值必须用中文输出..."
  LANG_INSTRUCTION.en: "All string values must be in English..."
```

## 字段词典双语

字典(`field-dict.ts`)的每个 `FieldOption` 都有 `{ key, zh, en, descZh?, descEn? }` 结构。`localizedLabel(opt, lang)` 和 `localizedDesc(opt, lang)` 是访问 helper。`FieldCombobox` / `OptionPicker` 内部 `useMemo` 把选项 localize 成 `string[]` 传下游。详见 [field-dictionary](../shared/field-dictionary.md)。

## 切语言后字段值不自动翻译

切换 zh↔en 时,**用户已经填的字段值保持原样**(不调 LLM 翻译)。理由:
- 避免歧义("水彩" → "Watercolor" 还是 "Water color" 还是 "Aquarelle"?)
- 切回原语言 = 原值,无意外
- UI 文案立刻切换,字段下拉候选立刻切换 —— 用户能感知到 lang 已切

## 未覆盖

- **自定义语言**(用户输入"日本語"等):未做。需要先做完整文案 i18n 提取 + LLM 翻译 cache。**已 memory 备忘**:扩展 `useLanguage` 走 LLM 翻译 + localStorage cache;字典 key 已是稳定 i18n 基础 —— 见 memory 文件 `inkast-llm-as-accelerator`。
