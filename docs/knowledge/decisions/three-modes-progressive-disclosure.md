# 三种生图模式 M1 / M2 / M3 渐进披露

inkast 实际有三种生图路径,**复杂度从简单到复杂阶梯式排开**。UI 用"手风琴展开"区分这三个状态,而不是把三个并列入口堆在同一屏。

## 三种模式

| | 输入 | LLM 参与 | 字段编辑器 | 用户群 | UI 状态 |
| --- | --- | --- | --- | --- | --- |
| **M1 直接生图** | 散文 | 无 | 不出现 | 新手 / 快速一次性 | 左宽中窄(不展开) |
| **M2 字段精修** | 字段 | 无 | 主舞台 | 老用户 / 精确控制 | 手风琴展开 + lockMode="m2" |
| **M3 AI 扩充** | 散文 → 字段 | 起润色 | 主舞台 | 多数用户 / 迭代 | 手风琴展开 + lockMode="ai-filled" |

**复杂度阶梯**:M1 < M2 ≤ M3。M2 和 M3 复杂度相近但**方向不同**——M2 是"完全人工",M3 是"人机协作"。

## 背景:为什么不能简单"三个并列入口"

V1 设计把三种入口同屏(散文 textarea 上面 + 字段编辑器底部 + 散文区"直接生图"按钮),问题:

1. 用户**进门要先理解三种模式**才能开始,摩擦最大
2. "AI 预填字段"用 primary 大墨绿按钮——长得像生图按钮,但实际只是填字段
3. 三个按钮在同屏视觉强调互相打架(primary / accent / accent 用色冲突)

## 入口设计

```
初始态(无文本,左宽中窄):
  [文本框](空)
  [▶ 直接生图(禁用)] [✦ AI 扩充到字段(禁用)]
  ── 或 ──
  ⊞ 跳过文本,直接编辑字段  ⌘E  ← M2 入口仅在这里出现

写完文本(布局不变,按钮激活):
  [文本框](有内容)
  [▶ 直接生图] [✦ AI 扩充到字段]
  ── 或 ──
  ⊞ 跳过文本,直接编辑字段  ⌘E
  ↑ M2 入口仍在,因为还没确定走哪条路

点 ▶ 直接生图 → M1:布局不变,右栏出现 loading tile,完成后是实际图
点 ✦ AI 扩充 → M3:手风琴翻转,左栏锁定显示文本,中栏字段被 AI 填好
点 ⊞ 跳过文本 → M2:手风琴翻转,左栏标"已锁定·无散文",中栏字段空白
```

## M1 为什么不触发手风琴

M1 的核心价值是**"快速试一张"**。如果点了"直接生图"触发手风琴展开,用户得点解锁才能继续改文本——破坏了"写一句→生图→改一句→再来一张"的轻盈轮回。

所以 M1 的 UI 信念是:**直接生图不算"进入工作模式"**,只是临时一次性输出。手风琴保持收起,左栏继续是主区,用户可以反复改文本再来一张。

## M2 入口为什么只在初始态出现

实际上 M2 入口在**有文本时仍然显示**(底部小链接),但点了会清空文本。

关键约束:M2 = 字段精修 = 无 LLM 介入。如果用户写了文本然后点 M2,我们**没有不调 LLM 的能力把文本拆到字段**——"语义解析散文"本来就是 LLM 的工作。所以 M2 进入时必须**丢弃文本**,这是 hard constraint。

实际场景里,想用 M2 的用户大概率**不会先写文本**——他直接来字段。所以"写完文本切 M2"几乎不存在。详见 [m2-entry-textless-only](./m2-entry-textless-only.md)。

## 解锁返回起草

锁定态(M2 / M3)显示"解锁"或"回到起草"链接。点了:
- `setLockMode(null)` → 手风琴翻回左宽中窄
- M3 解锁:prompt 字段保留(state 不变),但中栏 collapsed → UI 不渲染字段。用户能看到的就是回到初始的左栏 + textarea
- M2 解锁:同上,但 textarea 是空的(进 M2 时已清空)

**信念**:解锁=回到起草,字段不可见是有意的——如果用户想继续看字段,就不该解锁。

## 没做的:AI 持续建议

原型阶段讨论过"M3 模式下 AI 持续给修改建议,用户挑着采纳"(imagegen 方法论里的"模糊点反馈")。

**这版没做**——原因:
- 当前 `/api/draft-prompt` 只返回单次 `PromptDraft`,没有"持续建议"的 schema
- 实施需要后端改 prompt-engine + 共享契约加新类型 + 前端建议侧栏 UI
- 一次改动太多,先把手风琴+三栏主体落地

UI 上保留位置:M3 锁定态的左栏可以将来加 "AI 建议" 卡片(在锁定文本下方)。
