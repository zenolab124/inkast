B · 阶梯指示器

信念:把"散文 → AI 润色 → 字段微调 → 生图"做成显式三步路径。用户随时能看到自己在哪、能跳到哪。M1 = 停在 ①;M2 = 跳到 ③ 清空状态;M3 = 走完 ①②③。

教学性强,新用户看着指示器就知道工作流。代价:对老用户重复(每次都要看那个进度条);"阶梯"暗示有先后,但用户可能跳跃式工作;指示器占顶部一整条,挤压主区。

C · 模式 Tab

信念:三种模式是三种独立工作流,顶部 Tab 切换。每个 Tab 的视图针对该模式优化,没有视觉干扰。底层 prompt 状态在 Tab 间共享(切换不丢数据)。

视图最干净——每个模式只显示自己需要的元素。代价:用户得理解三个 Tab 的语义("快速""助手""精修"——开发者命名,用户可能不懂);切 Tab 有切换成本;Tab 切换时另一模式的细节不可见。

D · 左右分裂渐进

信念:左半永远是散文区,右半是字段编辑器。初始字段编辑器折叠成提示("写完文本展开")。用户可以同时看到两边——不强迫切换模式。

用户始终知道两种工作模式的存在,M1/M2/M3 都在视野内。代价:屏幕分两半,各边都不够宽;移动端必须折叠成单列;空字段编辑器占大块空间但没内容,有点浪费;M2 入口是右上角"清空文本进字段"——隐式。

E · 双入口卡片

信念:进门就让用户在两条路径中选——"写散文"(M1/M3) 或 "直接字段"(M2)。两条路径在物理上分开,各自有独立流程。

认知最清晰——用户进门就知道自己在做哪种。代价:每次进来都要选(对回访用户摩擦);两条路径独立维护,代码复杂度高;切换路径(从字段路径切回散文)需要明显的"返回入口"按钮。
