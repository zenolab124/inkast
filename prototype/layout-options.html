B · 两栏:左编辑器主 + 右 Gallery 常驻 + 顶部散文条

信念:字段编辑器是绝对主区,占 ~70% 宽。散文降级为顶部一条 strip(单行 + AI 预填按钮),不抢视觉权重。Gallery 在右侧常驻,生图完即时刷新。

取舍:编辑器有宽阔的空间,字段可以横向排得更舒服;Gallery 列 420px 是 2 列网格的舒适宽度。代价:散文区被压缩到一行,长散文需要展开;参考图 / 示例需要找新位置(我塞在散文 strip 的右侧)。

C · 上下分屏:上编辑区(Tab 切散文/字段)+ 下 Gallery 横滚

信念:用户有两种工作模式——"快速起草"(散文 + AI)和"精细控制"(字段)——两种模式互斥,用 Tab 切。无论哪个 Tab,底部 Gallery 横滚条始终可见,任务完成即刷新。

取舍:用 Tab 把"散文 vs 字段"显式表达,认知上更清晰(解决"3 个生图入口"问题)。代价:切换 Tab 时另一侧不可见,如果用户想"散文起草+字段精修"的两步流程,必须在 Tab 间来回切换。Gallery 横滚虽然始终可见但展示密度低(一屏 ~6 张)。

D · 单画布:字段编辑器全宽 + 右上 AI 浮卡 + 底部 Gallery 抽屉

信念:字段编辑器是绝对主区,占满主屏。散文 + AI 是"辅助工具",收进右上角浮卡(可折叠 / 可拖动)。Gallery 是"回收站",收进底部抽屉(默认展开 1 行,可上拉)。

取舍:最忠实表达"字段是核心,AI 是加速器"的产品决策。字段编辑器有最宽的空间。代价:浮卡浮在内容上方会遮挡(右上角的"基本"分组卡部分被压在浮卡下);浮卡 280px 给散文很挤;底部抽屉默认只显示 1 行 Gallery,要看全得上拉。复杂度最高。
